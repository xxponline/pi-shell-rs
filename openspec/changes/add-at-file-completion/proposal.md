# Proposal — `@文件` 补全

## Why

pi 的输入框支持 `@文件` 引用补全（附件/引用路径的即时候选），我们的补全菜单目前只覆盖斜杠命令与参数——输入 `@` 没有任何提示，文件路径只能全凭记忆手打。这是差异表后续批次中最后一项纯 TUI 侧能力（扩展命令参数补全因需上游 RPC 已明确不做）。

## What Changes

- 输入 `@` 触发**文件补全菜单**：识别光标前的 `@path` / `@"quoted path"` token，列出候选并复用既有补全菜单的渲染与键位（↑↓/Tab/回车/Esc）
- 候选生成对齐 pi：**基础目录前缀匹配**（cwd 下 `readdir`，大小写不敏感 startsWith、目录优先、字母序）+ **递归模糊搜索**（pi 用 `fd` 二进制：打分 exact 100 / startsWith 80 / 子串 50 / 路径 30、目录 +10，排序=分数→深度→长度→字典序，**取前 20**）；`fd` 不存在时回落为基础目录前缀候选（pi 为完全无候选——记为差异）
- 应用语义对齐 pi：文件补空格、**目录不补空格**（可继续下钻）、保留 `@` 前缀与 `~/`、`./`、绝对路径写法、含分隔符时自动加引号、光标落位对齐
- 路径解析支持 `~` 展开、相对 cwd、绝对路径；目录不存在/不可读 → 静默空候选（不报错）

## Capabilities

### New Capabilities

- **file-completion**：`@文件` 补全的触发、候选生成与菜单应用语义（独立于 slash 命令补全，未来可扩展普通路径补全）

### Modified Capabilities

（无——菜单键位复用 `slash-autocomplete` 既有约定，不改其需求）
